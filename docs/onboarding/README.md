# SafelyTold commercial and technical onboarding library

This folder is the controlled starting point for people who answer questions from prospects, clients, investors, funders, procurement teams and bid evaluators.

## Required reading

| Audience | Required manual | Purpose |
| --- | --- | --- |
| Sales, marketing, partnerships, customer success | [Commercial product onboarding](commercial-product-onboarding.md) | Explain SafelyTold accurately, qualify opportunities, run demonstrations and recognise escalation triggers. |
| Engineering, security, privacy, solution architecture, operations | [Technical escalation handbook](technical-escalation-handbook.md) | Answer technical due diligence, validate claims, scope deployments and manage technical escalations. |

Neither manual is a substitute for legal advice, a signed contract, a data-processing agreement, a security assessment or customer-specific solution design.

## Sources of truth

Use sources in this order:

1. Running production configuration and verified release evidence.
2. Current application and service code.
3. This onboarding library.
4. Current assurance, architecture and operations documents under `docs/`.
5. Historical proposals and feasibility documents only as background.

If two documents conflict, do not choose the more favourable statement. Escalate the conflict to Product and Technical Assurance.

## Document ownership

| Subject | Accountable owner |
| --- | --- |
| Product capability and roadmap | Product owner |
| Architecture, integration and deployment | Technical lead |
| Security controls and security questionnaires | Security lead |
| POPIA/GDPR roles, lawful basis and data-subject rights | Privacy/legal lead |
| Hotline operating model and 24/7 staffing | Operations lead |
| Pricing and commercial commitments | Commercial lead |
| Public claims and campaign material | Marketing lead with Product approval |

Review both manuals before every significant release and at least quarterly.
