# ADR-001: Modular Monolith before Microservices

- **Status:** Proposed (Phase 1)
- **Context:** §11, Appendix C, ADR list in proposal
- **Decision:** The initial backend will be a modular FastAPI monolith with clear domain packages (intake, cases, evidence, policy, integrations, analytics). Microservices will only be extracted after load, residency or ownership pressures justify the added operational complexity.
- **Consequences:**
  - Simplifies deployment, secrets, observability and RLS enforcement early on.
  - Requires strong conventions (package boundaries, service interfaces, transactional outbox) to keep modules decoupled.
  - Future service extraction must maintain API contracts + Temporal workflows.
- **Next Steps:** Document package structure in `/api/README.md`, enforce boundaries via lint/tests (e.g., import-lint), revisit decision after Phase 2 pilots.
